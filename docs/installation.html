Installation & Deployment Guide

Prepare your Incus host, build the single-binary console, configure environment variables, and deploy safely behind Caddy and systemd.

Requirements

  • Linux server running Incus (incusd) with a local Unix socket (/var/lib/incus/unix.socket).
  • Storage pool (ZFS recommended for instant copy-on-write snapshots).
  • Go 1.26+ to build from source (pure Go, including the SQLite driver—no CGO required).
  • Caddy on the host for automatic HTTPS certificates and domain routing.
  • Optional: any S3-compatible bucket (AWS S3, MinIO, Cloudflare R2, Backblaze B2) for off-site backups.

Host setup (Incus & Caddy)

1. Storage pool & private bridge

Ensure Incus has at least one storage pool and a managed NAT bridge (incusbr0 by default) for instance private networking:

incus storage create default zfs size=100GiB
incus network create incusbr0 ipv4.address=10.10.0.1/24 ipv4.nat=true

2. Caddy integration

Enable Caddy's admin API in /etc/caddy/Caddyfile so the console can push domain updates without restarting Caddy, and import the console's site config if desired:

{
    admin localhost:2019
}

# Optional if using CADDY_CONFIG_PATH instead of CADDY_ADMIN_URL:
# import /etc/caddy/cloud-console.caddy
Tip: Put the console itself behind Caddy with HTTPS before exposing it to the internet, and set CONSOLE_BASE_URL=https://console.example.com.

Build the binary

Templates, stylesheets, JavaScript, fonts, and the WebAssembly terminal assets are embedded directly into the binary:

git clone https://github.com/PeacefullCloud/cloud-console
cd cloud-console

# Static release build
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X main.version=1.0.0" -o cloud-console .

Configuration & .env

Peaceful Cloud Console loads .env from its working directory automatically (or the path in CONSOLE_ENV_FILE). Real environment variables and systemd Environment= directives always override values in .env.

cp .env.sample .env
chmod 600 .env

Before enabling OIDC SSO or TOTP in production, generate strong encryption keys:

# 32-byte hex keys for SSO client secrets and TOTP secrets
openssl rand -hex 32   # use for CONSOLE_SSO_KEY
openssl rand -hex 32   # use for CONSOLE_SECRET_KEY

Systemd deployment

Install the binary to /usr/local/bin/cloud-console, place configuration in /etc/peaceful-cloud/console.env (mode 0600), and create a systemd unit:

# /etc/systemd/system/cloud-console.service
[Unit]
Description=Peaceful Cloud Console
After=network-online.target incus.service
Wants=incus.service

[Service]
Type=simple
DynamicUser=yes
SupplementaryGroups=incus-admin
StateDirectory=peaceful-cloud
WorkingDirectory=/var/lib/peaceful-cloud
EnvironmentFile=/etc/peaceful-cloud/console.env
ExecStart=/usr/local/bin/cloud-console
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target

Enable and start the service:

sudo systemctl daemon-reload
sudo systemctl enable --now cloud-console

Caddy reverse proxy site block

Proxy your console domain to 127.0.0.1:8080. Caddy handles HTTPS certificates and WebSocket upgrades for the browser terminal automatically:

console.example.com {
    reverse_proxy 127.0.0.1:8080
}

First run & verification

  1. Verify the health endpoint returns HTTP 200: 
    curl -fsS http://127.0.0.1:8080/healthz
  2. If CONSOLE_ADMIN_PASSWORD was left empty, read the generated initial password from <data_dir>/initial-admin-password (mode 0600).
  3. Sign in as admin, change your password in Settings → Account, enable Two-factor authentication, and delete initial-admin-password.
