Architecture & Management Guide

How it works

Peaceful Cloud Console uses a single Go process with no external message queue or cache:

Browser (HTML + HTMX + wterm WASM)
   │  HTTPS via Caddy
   ▼
Go Backend (cloud-console)
   ├── SQLite (users, sessions, domains, dedicated IPs, jobs, metrics, audit log)
   ├── Incus Unix Socket (containers, VMs, ZFS storage, snapshots, exec PTY/SFTP)
   └── Caddy Admin API / Caddyfile (automatic TLS + reverse proxy routes)
  • Incus owns infrastructure state: running status, private IPs, CPU/memory counters, storage pools, and snapshots are read directly from Incus.
  • SQLite owns console metadata: accounts, hashed sessions, ownership mappings, domains, backup records, sampled metrics, and audit logs.
  • Background job worker pool: long-running actions (instance provisioning, rebuilds, backups) run in-process with live progress polling in the UI.

Users, roles & quotas

Access is enforced by role and per-instance ownership across all pages, APIs, and WebSockets:

RoleScopeCapabilities
adminEntire hostManage all instances, host storage/networks, dedicated IP pool, users, quotas, SSO providers, and Caddy config.
operatorOwned instancesCreate, start, stop, resize, snapshot, backup, attach domains, and open web terminal/SFTP on owned instances.
viewerOwned instancesRead-only access to owned instance metrics, status, domains, and logs (no terminal or mutating actions).

Administrators can manage accounts, reset locked-out user passwords, set per-user instance quotas (0 = unlimited up to CONSOLE_MAX_INSTANCES), and reassign instance ownership in Settings → Users and each instance's Settings tab.

Security, 2FA & SSO

  • Sessions & CSRF: 32-byte random session tokens are SHA-256 hashed before storage; HttpOnly, SameSite=Lax cookies and double-submit CSRF tokens guard every mutating request.
  • Two-Factor Authentication (TOTP): Users can enroll an authenticator app and receive 8 one-time recovery codes. TOTP secrets are encrypted at rest with CONSOLE_SECRET_KEY (or <data_dir>/secret.key).
  • OIDC Single Sign-On: Admins can configure OIDC providers under Settings → SSO. Set CONSOLE_SSO_KEY before adding providers so client secrets are encrypted at rest.
  • Rate limiting: Failed password and 2FA verifications are throttled in memory by username and client IP.

Domains & dedicated public IPs

Domains & automatic HTTPS

Instances receive private RFC1918 addresses on the Incus bridge. Attaching a domain in an instance's Domains tab updates Caddy and automatically issues/renews Let's Encrypt TLS certificates once DNS points to the host.

When CONSOLE_PLATFORM_DOMAIN is configured (e.g. cloud.example.com), instances can also receive instant wildcard subdomains without manual DNS per instance.

Dedicated public IPs (Admin-only pool)

If your server has additional routed public IPs or secondary Elastic IPs, administrators can register them under Networking → Add dedicated IP and assign them 1:1 to an instance (from Networking or the instance's Networking tab). The console configures Incus network forwards with 1:1 port forwarding and SNAT where supported.

Port forwarding & bridge isolation

Individual TCP or UDP ports (external ports 10000–60000) can be exposed per instance from the Networking tab. New instances on the bridge have MAC and IPv4/IPv6 filtering enabled to prevent ARP or IP spoofing between tenants.

Web terminal & SFTP file manager

The browser terminal attaches to an interactive Incus exec session as cloud-user (configurable via CONSOLE_TERMINAL_LOGIN_USER) without exposing SSH ports or storing instance private keys in the browser.

  • New instances are provisioned with passwordless sudo for cloud-user and any selected vault SSH keys.
  • The companion SFTP panel connects through Incus exec to sftp-server and closes automatically on logout, expiry, or password change.
  • For public deployments, set CONSOLE_TERMINAL_ALLOWED_HOSTS to your public console hostname to prevent DNS-rebinding attacks against the WebSocket endpoint.

Snapshots & backups

  • Snapshots: Instant ZFS/storage copy-on-write checkpoints stored on the same pool. Set CONSOLE_SNAPSHOT_INTERVAL_HOURS > 0 and CONSOLE_SNAPSHOT_KEEP to automate scheduled auto-* snapshots.
  • Backups: Full portable instance archives written to <data_dir>/backups and optionally uploaded to S3-compatible object storage (configure S3_ENDPOINT, S3_BUCKET, S3_ACCESS_KEY, and S3_SECRET_KEY).

Monitoring, Prometheus & audit logs

  • Health check: GET /healthz returns 200 ok when Incus is reachable, or 503 otherwise.
  • Prometheus metrics: Set CONSOLE_METRICS_TOKEN and scrape GET /metrics with Authorization: Bearer <token>.
  • Failure alerts: Set CONSOLE_ALERT_WEBHOOK_URL to send JSON webhook notifications when background jobs fail.
  • Audit log: Every mutating action (logins, instance lifecycle, IP assignments, domain edits, user changes) is recorded in Activity and exportable to CSV by admins.

Upgrades & data backup

SQLite schema migrations embedded in the binary apply automatically on startup.

Safe upgrade steps

  1. Back up your critical console state before upgrading:
    • <data_dir>/console.db (console metadata)
    • <data_dir>/secret.key (if CONSOLE_SECRET_KEY is not set in env)
    • Your .env / console.env (contains CONSOLE_SSO_KEY and integration secrets)
  2. Build or download the new cloud-console binary and replace the old binary.
  3. Restart the service and check logs and /healthz: 
    sudo systemctl restart cloud-console
curl -fsS http://127.0.0.1:8080/healthz
